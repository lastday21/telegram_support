# SmartHelper

Приложение записывает звук или делает снимок экрана по горячей клавише, получает
ответ от Яндекса и отправляет результат в заданный чат Telegram.

## Как теперь устроена работа

```text
Программа Windows ──> сервер в Docker ──> Yandex Cloud
                              │
                              └──────────> Telegram

Telegram-бот ───────> сервер в Docker ──> Yandex Cloud
```

Программа Windows не содержит ключ Яндекса, токен Telegram и идентификатор
чата. Она знает только адрес сервера и отдельный заменяемый ключ доступа.

Docker Compose запускает два процесса:

- `server` принимает запросы программы Windows на порту `8000`;
- `telegram-bot` принимает сообщения только из чата `TG_CHAT_ID`.

Все запросы к Яндексу проходят через общую ограниченную очередь сервера.
По умолчанию одновременно выполняются два запроса, ещё восемь могут ожидать.
Это ограничение действует и для программы Windows, и для Telegram-бота.

По умолчанию порт сервера доступен только на текущем компьютере.

## Первый запуск

### 1. Настройте сервер

Скопируйте `.env.example` в `.env` и заполните четыре секретных значения:

```dotenv
YC_API_KEY=
YC_FOLDER_ID=
YC_MODEL=qwen3-235b-a22b-fp8/latest
TG_BOT_TOKEN=
TG_CHAT_ID=

YANDEX_MAX_CONCURRENT=2
YANDEX_QUEUE_SIZE=8
YANDEX_QUEUE_TIMEOUT=300
YANDEX_RETRY_DELAYS=0.5,1.5
YANDEX_FAILURE_LIMIT=5
YANDEX_RECOVERY_SECONDS=30
HTTP_MAX_CONCURRENT=16
HTTP_REQUEST_LIMIT=120
HTTP_RATE_WINDOW=60
HTTP_MAX_BODY_SIZE=23068672
AUTH_FAILURE_LIMIT=5
AUTH_FAILURE_WINDOW=60
AUTH_BLOCK_SECONDS=300
HEALTH_CACHE_SECONDS=30
HEALTH_TIMEOUT=5
```

`YANDEX_QUEUE_TIMEOUT` задаёт время ожидания свободного места в секундах.
Если очередь заполнена, сервер отвечает кодом `429`. Если ожидание истекло —
кодом `503`.

Временные ошибки соединения, ответы `429` и ошибки Яндекса `5xx` повторяются
через интервалы `YANDEX_RETRY_DELAYS`. После пяти подряд неудачных обращений
сервер на 30 секунд прекращает новые обращения к Яндексу, чтобы не усиливать
сбой внешней службы.

Сервер одновременно обрабатывает не больше 16 входящих запросов и принимает
не больше 120 запросов от одного адреса за минуту. Общий размер запроса
ограничен 22 МБ до разбора загруженного файла. После пяти неверных ключей
доступ с этого адреса блокируется на пять минут.

По умолчанию используется актуальная версия Qwen3 235B, которая лучше подходит
для расчётных задач и программирования. Для более быстрых ответов можно указать
`YC_MODEL=aliceai-llm/latest` или `YC_MODEL=aliceai-llm-flash/latest`.

Создайте общий ключ между Docker и программой Windows:

```powershell
python scripts/configure_access.py
```

Команда создаст два файла, не показывая ключ на экране:

```text
<проект>\.env.access
%APPDATA%\SmartHelper\.env
```

Оба файла исключены из репозитория. В сборку Windows они не добавляются.

### 2. Запустите Docker

```powershell
docker compose up -d --build
```

Проверка запуска самого сервера:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/live
```

Docker использует именно эту проверку, поэтому временная недоступность Яндекса
или Telegram не делает работающий контейнер неисправным.

Проверка полной готовности внешних служб:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/ready
```

Подробная общая проверка:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

Ожидаемый ответ:

```json
{
  "status": "ok",
  "checks": {
    "settings": "ok",
    "yandex": "ok",
    "telegram": "ok"
  },
  "queue": {
    "active": 0,
    "waiting": 0,
    "max_concurrent": 2,
    "max_waiting": 8
  }
}
```

Проверки `/ready` и `/health` подтверждают наличие настроек, доступность Яндекса
и правильность токена Telegram. Результат сохраняется на 30 секунд. Если хотя
бы одна служба недоступна, оба адреса отвечают кодом `503`. `/live` при этом
продолжает отвечать `200`, пока сам сервер способен принимать запросы.

### 3. Подготовьте Windows

FFmpeg включается внутрь собранной программы, отдельно устанавливать его не
нужно. Для записи общего звука компьютера можно включить устройство Stereo Mix.
Если оно отключено, запись продолжит работать только с микрофоном. Имена
микрофона и микшера можно указать в `%APPDATA%\SmartHelper\.env`:

```dotenv
MIC_DEVICE=
MIX_DEVICE=
```

Если значения пустые, приложение попробует найти устройства само.

Для запуска из исходников установите `uv` и подготовьте клиентское окружение:

```powershell
uv sync --frozen --extra client --no-dev
```

Запуск основной программы:

```powershell
uv run --frozen --extra client --no-dev python -m app.desktop
```

Окно настроек запускается отдельно:

```powershell
uv run --frozen --extra client --no-dev python -m app.settings_app
```

Если клиентский файл ещё не создан, окно настроек всё равно откроется. Укажите
в нём адрес сервера и значение `APP_ACCESS_TOKEN` из серверного файла
`.env.access`. После сохранения будет создан файл
`%APPDATA%\SmartHelper\.env`.

В этом же окне можно задать числовой идентификатор чата Telegram, запустить,
остановить или перезапустить основную программу. После изменения настроек
нажмите «Сохранить настройки», затем «Перезапустить».

## Горячие клавиши

- `Alt+Q` — начать или остановить запись;
- нажатие колёсика мыши — ответ по всему экрану;
- `Alt` + нажатие колёсика — добавить видимую часть большого текста;
- `Ctrl` + нажатие колёсика — очистить ранее собранный большой текст;
- `Alt+1`–`Alt+5` — пять дополнительных команд.

Клавиша микрофона, пять сочетаний и все шесть подсказок меняются в отдельной
программе настроек. Кнопка мыши всегда остаётся нажатием колёсика.

Снимок, распознанный текст и ответ передаются через сервер. Облачные ключи на
компьютер с горячими клавишами не отправляются.

Для заданий с большим исходным текстом сначала покажите начало текста и
нажмите `Alt` вместе с колёсиком. Прокрутите страницу и повторите действие
для каждой следующей части. Одинаковые строки из соседних снимков удаляются.
Когда на экране появится вопрос, нажмите колёсико без дополнительных клавиш:
помощник приложит весь собранный текст к текущему заданию. Контекст сохраняется
для следующих вопросов к тому же тексту. Перед новым текстом очистите его через
`Ctrl` + нажатие колёсика. Контекст хранится только в памяти запущенной
программы и ограничен 120 000 знаков.

Снимки также отправляются в Telegram перед ответом. Все ещё не отправленные
части большого текста объединяются со снимком текущего вопроса в один альбом.
Telegram принимает в один альбом не больше десяти снимков, поэтому более
длинный набор автоматически делится на несколько последовательных альбомов.
При следующих вопросах повторно отправляется только новый снимок вопроса.

Каждый сделанный снимок сохраняется локально в
`%LOCALAPPDATA%\SmartHelper\screenshots`. В папке остаются последние 100
снимков; при появлении 101-го самый старый удаляется. Папка находится вне
проекта и не попадает в репозиторий.

Готовый ответ на 20 секунд появляется в правом верхнем углу экрана. Windows
исключает это окно из обычной записи и демонстрации экрана. Перед снимком,
который делает сам SmartHelper, окно дополнительно скрывается; если скрытие не
подтвердилось, снимок не создаётся. Окно можно закрыть раньше клавишей `Esc` или
крестиком. Показ окна можно включить или выключить галочкой в программе
настроек.

Повторные нажатия защищены от дребезга и выполняются последовательно. Если
предыдущее действие ещё не завершено, программа не запускает второй экземпляр
записи или обработки снимка.

Получение и показ ответа не зависят от доступности Telegram. Сообщения
отправляются отдельной очередью с повторными попытками, а длинный текст
автоматически делится на несколько сообщений.

Основная программа работает без окна и без значка рядом с часами. Повторный
запуск не создаёт второй экземпляр. Нажатие колёсика перехватывается, поэтому
открытая программа не включает автопрокрутку и не получает это нажатие.

Пользовательские настройки хранятся локально в
`%APPDATA%\SmartHelper\settings.json` и загружаются при следующем запуске.

Журнал работы программы хранится в:

```text
%LOCALAPPDATA%\SmartHelper\logs\smarthelper.log
```

При достижении 2 МБ журнал автоматически архивируется. Сохраняются пять
предыдущих файлов.

Длинная запись автоматически делится на части перед распознаванием и затем
собирается в один текст. Сервер принимает WAV-файлы размером до 20 МБ — это
примерно 10 минут для формата 16 кГц, один канал, 16 бит.

## Команды Telegram

- `/start` и `/help` — справка;
- `/prompts` — список подсказок;
- `/p <номер>` — применить подсказку;
- обычное текстовое сообщение — получить ответ.

Сообщения из других чатов бот игнорирует.

## Сборка программы Windows

Установите `uv` и выполните:

```powershell
uv sync --frozen --extra client --no-dev --group build
uv run --frozen --extra client --no-dev --group build pyinstaller --clean build.spec
```

В папке `dist` появятся два файла:

- `SmartHelper.exe` — невидимый запуск основной программы;
- `SmartHelperSettings.exe` — отдельное окно настроек.

Файл `.env` и серверные секреты в них не включаются. Адрес сервера и ключ
соединения читаются из:

```text
%APPDATA%\SmartHelper\.env
```

Выбор модели, сочетания клавиш и подсказки читаются из:

```text
%APPDATA%\SmartHelper\settings.json
```

## Автоматическая проверка и сборка

После отправки изменений в `main` GitHub автоматически:

- проверяет оформление и типы;
- запускает тесты;
- собирает и публикует серверный образ
  `ghcr.io/lastday21/telegram_support:latest`;
- запускает собранный серверный контейнер и ждёт успешного состояния `/live`;
- создаёт перечень компонентов серверного образа в формате SPDX;
- останавливает сборку при исправимых уязвимостях высокой или критической
  опасности;
- подписывает происхождение опубликованного серверного образа и его перечень
  компонентов через GitHub и Sigstore;
- собирает обе программы Windows и сохраняет их в результатах запуска под
  именем `SmartHelper-Windows` на 14 дней.

Сборка Windows также выполняется при проверке запросов на слияние. После сборки
обе программы запускаются в режиме самопроверки, а рядом с ними создаётся файл
`SHA256SUMS.txt` с контрольными суммами.

Для подписи выпусков добавьте в секреты GitHub:

- `WINDOWS_CERTIFICATE_BASE64` — сертификат `.pfx` в Base64;
- `WINDOWS_CERTIFICATE_PASSWORD` — пароль сертификата.

Обычная сборка без сертификата остаётся доступной. Для меток вида `v*`
сертификат обязателен, поэтому неподписанный выпуск опубликован не будет.

Локальная разработка, Docker и GitHub используют одинаковые точные версии
пакетов из `uv.lock`.

Чтобы обновить сервер из опубликованного образа:

```powershell
docker compose pull
docker compose up -d --no-build
```

Для локальной сборки из исходников по-прежнему используется:

```powershell
docker compose up -d --build
```

## Сервер на другом компьютере

Если Docker работает не на том же компьютере, перед сервером нужно настроить
HTTPS, а в клиентском файле указать внешний адрес:

```dotenv
SERVER_URL=https://helper.example.ru
```

Публиковать порт `8000` напрямую в интернет не следует. Значение
`APP_ACCESS_TOKEN` на сервере и в программе Windows должно совпадать.
