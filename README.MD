# SmartHelper

Приложение записывает звук или делает снимок экрана по горячей клавише, получает
ответ от Яндекса и отправляет результат в заданный чат Telegram.

## Как теперь устроена работа

```text
Программа Windows ──> сервер в Docker ──> Yandex Cloud
                              │
                              └──────────> Telegram

Telegram-бот ───────> отдельный процесс в Docker ──> Yandex Cloud
```

Программа Windows не содержит ключ Яндекса, токен Telegram и идентификатор
чата. Она знает только адрес сервера и отдельный заменяемый ключ доступа.

Docker Compose запускает два процесса:

- `server` принимает запросы программы Windows на порту `8000`;
- `telegram-bot` принимает сообщения только из чата `TG_CHAT_ID`.

По умолчанию порт сервера доступен только на текущем компьютере.

## Первый запуск

### 1. Настройте сервер

Скопируйте `.env.example` в `.env` и заполните четыре секретных значения:

```dotenv
YC_API_KEY=
YC_FOLDER_ID=
TG_BOT_TOKEN=
TG_CHAT_ID=
```

Создайте общий ключ между Docker и программой Windows:

```powershell
python scripts/configure_access.py
```

Команда создаст два файла, не показывая ключ на экране:

```text
<проект>\.env.access
%APPDATA%\SmartHelper\.env
```

Оба файла исключены из репозитория. В сборку Windows они не добавляются.

### 2. Запустите Docker

```powershell
docker compose up -d --build
```

Проверка состояния сервера:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

Ожидаемый ответ:

```text
status
------
ok
```

### 3. Подготовьте Windows

Установите FFmpeg и убедитесь, что команда `ffmpeg` доступна из PowerShell.
Для записи общего звука компьютера включите устройство Stereo Mix. Имена
микрофона и микшера можно указать в `%APPDATA%\SmartHelper\.env`:

```dotenv
MIC_DEVICE=
MIX_DEVICE=
```

Если значения пустые, приложение попробует найти устройства само.

Запуск из исходников:

```powershell
python -m app.desktop
```

## Горячие клавиши

- `Alt+Q` — начать или остановить запись;
- `Alt+1` — короткий ответ по тексту на экране;
- `Alt+2`–`Alt+9` — остальные варианты ответа из `app/prompts.py`.

Снимок, распознанный текст и ответ передаются через сервер. Облачные ключи на
компьютер с горячими клавишами не отправляются.

Повторные нажатия защищены от дребезга и выполняются последовательно. Если
предыдущее действие ещё не завершено, программа не запускает второй экземпляр
записи или обработки снимка.

Рядом с часами отображается значок состояния:

- зелёный — программа готова или ответ получен;
- красный — идёт запись или произошла ошибка;
- жёлтый — запрос обрабатывается;
- серый — сервер недоступен.

В меню значка можно повторно проверить сервер или завершить программу.

Длинная запись автоматически делится на части перед распознаванием и затем
собирается в один текст. Сервер принимает WAV-файлы размером до 20 МБ — это
примерно 10 минут для формата 16 кГц, один канал, 16 бит.

## Команды Telegram

- `/start` и `/help` — справка;
- `/prompts` — список подсказок;
- `/p <номер>` — применить подсказку;
- обычное текстовое сообщение — получить ответ.

Сообщения из других чатов бот игнорирует.

## Сборка программы Windows

Установите средства разработки и выполните:

```powershell
pip install -r requirements-client.txt
pip install -r requirements-dev.txt
pyinstaller --clean build.spec
```

Готовый файл появится по пути `dist\SmartHelper.exe`. Файл `.env` и серверные
секреты в него не включаются. Клиентские настройки читаются только из:

```text
%APPDATA%\SmartHelper\.env
```

## Автоматическая проверка и сборка

После отправки изменений в `main` GitHub автоматически:

- проверяет оформление и типы;
- запускает тесты;
- собирает и публикует серверный образ
  `ghcr.io/lastday21/telegram_support:latest`;
- собирает `SmartHelper.exe` и сохраняет его в результатах запуска под именем
  `SmartHelper-Windows` на 14 дней.

Чтобы обновить сервер из опубликованного образа:

```powershell
docker compose pull
docker compose up -d --no-build
```

Для локальной сборки из исходников по-прежнему используется:

```powershell
docker compose up -d --build
```

## Сервер на другом компьютере

Если Docker работает не на том же компьютере, перед сервером нужно настроить
HTTPS, а в клиентском файле указать внешний адрес:

```dotenv
SERVER_URL=https://helper.example.ru
```

Публиковать порт `8000` напрямую в интернет не следует. Значение
`APP_ACCESS_TOKEN` на сервере и в программе Windows должно совпадать.
